# 독단전행 — 만드는 차례

```
1. 문서목록.json    사건별로 고른 JACAR 레퍼런스 코드 (사람이 검색해 고른다)
2. jacar_fetch.py   --list 로 PDF를 받아 pages/<코드>-NN.jpg 로 쪼갠다
3. 옮긴다            서브에이전트. pages/<코드>-*.jpg 를 직접 읽어 tr/<코드>.json
4. make_docs.py     reading/docs.json 을 짓는다
5. ../열람기/build_site.py
```

## 이 문서철만 다른 것 — 소스가 하나가 아니다

다른 문서철은 FRUS 한 시리즈, CREST 한 시스템, 외무성 한 간행물처럼 **출처가
하나**였다. 이 문서철은 다르다. 1928년 장쭤린 폭살은 외무성 외교사료관,
나머지 다섯 사건은 방위성 방위연구소 소장이다. **사건(event) 이 문서철의
1차 단위이고, 그 아래 문서가 온다** — `KOREA_1950_53`이 날짜로 죽 이어지는
것과 달리, 이건 1928~1939년에 흩어진 여섯 개 사례를 나란히 놓는 것이다.

`collection.json`의 `groups`(A~E, X 여섯 칸)에 사건을 하나씩 건다.

    A 장쭤린 폭살(1928)   B 만주사변(1931)   C 러허작전(1933)
    D 노구교 사건(1937)   E 태원작전(1937)   X 노몬한 사건(1939)

## JACAR에서 받는 법

`jacar_fetch.py`의 머리말에 적어 두었다. 요점만: **메타 페이지(`/das/meta/`)는
SPA 껍데기뿐이라 못 쓴다.** 뷰어 페이지(`/das/image/<코드>#1`)의 HTML 안에
PDF.js에 넘기는 실제 PDF 경로가 이미 박혀 있어서, 브라우저 없이 `curl` 수준
(`urllib`)으로 받아진다. `--expand <簿冊코드>`로 묶음의 하위 문서 코드를
뽑을 수 있는데, **JACAR 목록이 20건 단위로 자바스크립트 페이지네이션**이라
21건이 넘는 묶음은 뒷부분을 사람이 브라우저로 열어 코드를 보태야 한다.
(만주사변 첫 묶음이 23건인데 20건만 자동으로 잡힌 게 그래서다 — `문서목록.json`
의 `note`에 적어 두었다.)

## 문서를 고르는 기준 — 이 문서철엔 "일단 다 받는다"가 없다

CREST_전쟁처럼 날짜 창으로 통째로 긁어 오는 문서철이 아니다. 방위연구소
소장만 해도 **만주사변 자료군 하나가 414책**이다 — 다 받으면 감당이 안
된다. 그래서 사건마다 "지휘 계통·독단 여부"를 정면으로 다루는 절만
사람이 목차를 보고 골랐다(`문서목록.json`). 고른 기준은 이어가기.md의
「주제에 문서를 고르는 기준」과 같다 — **이 문서를 빼면 다음 서사가
이해되지 않는가.**

**러허 작전은 아직 못 골랐다.** 노구교·노몬한과 달리 이 사건만 모은
자료군이 없고, `陸軍省大日記` 계열에 225건이 흩어져 있어 검색으로
후보를 추리는 데 시간이 더 든다. `문서목록.json`의 `jehol-1933.docs`가
빈 배열인 채로 남아 있는 이유다.

## 옮기는 사람에게 — 필체가 사건마다 다르다

노몬한 `事件記録`(1950년 육군성이 정리한 것)와 장쭤린 사건 자료는 **활자**다.
나머지(만주사변 정보철, 노구교·태원 관련)는 **손글씨**이고 초서가 섞여
있다. 손글씨 쪽은 시간이 훨씬 더 걸린다는 걸 감안해 묶음을 짤 것.

## 원칙

`TRANSLATION_SPEC.md`에 다 적어 두었다. 요점 셋만: **OCR 초벌이 없다**(처음부터
지면을 직접 읽는다), **부대 번호·날짜·인원수를 고치지 마라**(CREST_전쟁과
같은 이유), **"누가 결정했고 도쿄는 언제 알았는가"가 나오는 대목은 반드시
`key_points_ko`에 남겨라**(이 문서철이 존재하는 이유).
