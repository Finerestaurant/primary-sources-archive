# 사료 판독·번역 파이프라인

스캔 이미지 → 텍스트 → 교정된 영문 + 한국어 번역 → 읽을 수 있는 문서.

```
ndl_download.py    NDL IIIF에서 페이지 이미지 받기       (무료)
ocr_pages.py       macOS Vision OCR → 텍스트            (무료 · 면당 1.4초)
segment.py         면 → 문서 경계 찾기 + 건명 배정       (무료)
translate_docs.py  LLM 교정 + 번역 → 조각별 JSON         (유료)
assemble_docs.py   조각 → 문서 단위로 합치기
make_docs.py       → 공용 열람기 규격으로 변환
../../열람기/build.py  → reader.html                     (공용)
```

## 면이 아니라 문서가 단위다

처음에는 면 단위로 번역했다. 351면을 351건으로 다루니 읽을 수가 없었다.
한 전문이 세 면에 걸치고, 한 면에 두 문서가 실린다.
그래서 `segment.py`를 넣어 **먼저 문서 경계를 찾고** 번역한다.

경계를 찾는 근거는 NDL 메타데이터의 `dcndl:alternative` — NDL이 매긴 수록 문서
목록이다. 이게 사실상 목차라서, 지어내지 않고도 351면을 66건으로 묶을 수 있었다.

| | 면 단위 (옛 방식) | **문서 단위 (지금)** |
|---|---|---|
| 항목 수 | 351 | **66** |
| 문맥 | 면마다 끊김 | 전문 한 통이 한 덩어리 |
| 목차 | 날짜 나열 | **건명별 주제 묶음** |

---

## 핵심 설계: 모델에게 "읽어라"가 아니라 "고쳐라"를 시킨다

판독은 OCR이 이미 한다. LLM은 OCR 오류를 고치고 번역만 한다.

| | 이미지를 LLM에 직접 | **OCR 먼저 (이 방식)** |
|---|---|---|
| 모델 요구조건 | 비전 모델 필수 | **텍스트 모델이면 됨** |
| 페이지당 입력 | 이미지 약 2,500 토큰 | 텍스트 **약 500 토큰** |
| 판독 비용 | 모델 요금에 포함 | **0원** (로컬·오프라인) |
| 정확도 | 모델이 판독+번역을 동시에 | 모델이 **교정에 집중** |

macOS Vision OCR의 실제 성능(이 자료 기준): 본문은 거의 정확하고, 오류는 전부 전형적인 OCR 혼동이다.

```
1s→is   1n→in   11st→list   or→of   ot→of   tor→for
Kores→Korea   Ary→Army   INPO→INFO   CINCPE→CINCFE   ND→NND
```

LLM이 이런 패턴을 고치는 건 쉽고 싸다. 반대로 스캔 이미지에서 처음부터 읽어내는 건 비싸고 틀리기 쉽다.

## 실행

### 1. 다운로드 (PDM 자료만)

```bash
pip install img2pdf
python ndl_download.py 9850431        # → ndl_9850431/ (351장, 폭 1600px)
```

### 2. OCR — 무료·로컬

```bash
pip install ocrmac                    # macOS Vision 래퍼
python ocr_pages.py ndl_9850431 ocr_9850431
```

**macOS 전용.** 다른 OS라면 Tesseract(`pytesseract`)나 PaddleOCR로 대체 — 이 자료(타자기 영문)에서는 Tesseract도 충분하다.

원본 OCR을 그대로 남긴다. 여기서 오탈자를 고치려 하지 말 것 — 다음 단계의 일이고, 원본을 남겨야 대조가 가능하다.

### 3. 문서 경계 찾기 — 무료

```bash
python segment.py ../pid_9850431 documents.json
```

면을 문서로 묶고 NDL 건명을 배정한다. LLM을 쓰지 않는다.
배정이 잘 안 될 때 볼 상수 세 개:

```python
RARE_DF = 0.15      # 이 비율 미만으로 등장하는 낱말을 '희귀어'로 본다
MIN_SCORE = 0.50    # IDF 가중 일치율 하한
```

건명 대조는 **SUBJECT 줄만** 쓴다. 문서 전체 낱말로 맞추면 흔한 말이 다 걸려
`Withdrawal from Korea` 하나에 37건이 붙는다. 여기에 IDF 가중과 희귀어 요구를
더해 81건→66건, 배정률 40%→61%가 됐다.

### 4. 교정 + 번역

```bash
python translate_docs.py ../pid_9850431 20      # 20건씩 끊어서
```

- **이어달리기 가능** — 이미 된 조각은 건너뛴다.
- 조각 계획을 `_chunks.json`에 남긴다. `MAX_PAGES`를 바꾸면 경계가 밀려
  이전 결과와 어긋나므로, **어긋나면 아무 일도 하지 않고 멈춘다.**
- 표가 긴 문서는 영문만 전사하고 한국어는 요약한다. 안 그러면 출력이 잘린다.

### 5. 조립 + 화면

```bash
python assemble_docs.py ../pid_9850431/documents.json \
                        ../pid_9850431/tr_docs \
                        ../pid_9850431/reading
python make_docs.py
python "../../열람기/build.py" ../pid_9850431/reading/collection.json
```

| 파일 | 용도 |
|---|---|
| `reading/index.md` | 건명별 → 시간순 목차 |
| `reading/read.md` | 전문 (마크다운) |
| `reading/docs.json` | 조립 결과 — 이 문서철의 구조 |
| `reading/reader_docs.json` | **공용 열람기 규격**으로 옮긴 것 |
| `reading/reader.html` | 열람기 |

**화면은 공용이다.** `../../열람기/`에 있고 FRUS 문서철과 같은 것을 쓴다.
자료마다 다른 것은 `make_docs.py` 하나가 흡수한다 — 규격은 `../../열람기/SCHEMA.md`.

`docs.json`과 `reader_docs.json`을 **따로 두는 이유**는, 같은 자리에 덮어쓰면
`assemble_docs.py`를 다시 돌릴 때 규격 파일이 날아가기 때문이다.

## 프롬프트 설계에서 신경 쓴 것

`translate_docs.py`의 `SYSTEM` 상수에 있다. 요점만:

**1. 도메인 용어집을 넣었다.** `CINCFE` `CG USAFIK` `TOO` `MCN` `UNTCOK` `TFGCG` 같은 약어와, 일본식 음독 지명(`Keijo` `Jinsen` `Fusan`…)의 한국 지명 대응. 없으면 모델이 임의로 풀어 쓰거나 틀린다.

**2. 원문을 현대화하지 말라고 명시했다.** `Chosen` `Keijo` `Jap` 같은 시대 표기를 그대로 둔다. 원저자의 문법 오류도 고치지 않는다. 사료이지 산문이 아니다.

**3. 판독 불가는 지어내지 말고 표시하게 했다.** 영문 `[illegible]` / 한국어 `[판독불가]`. **아카이브 작업에서 가장 중요한 규칙이다** — 그럴듯한 창작이 섞이면 자료 전체를 못 쓴다.

**4. 구조화 출력.** 문서종류·날짜·발신·수신·전문번호·기밀등급·요지·인물/지명/부대를 필드로 뽑는다. 그래야 목차와 검색이 만들어진다.

**5. 신뢰도를 자체 보고하게 했다.** `confidence: low`인 면은 `index.md` 하단에 따로 모아서 원본 대조 대상으로 표시한다.

## ⚠️ 한계

- **한국어는 기계 번역이고, 영문도 OCR 교정본이다.** 게임이나 문서에 인용하기 전에 반드시 원본 스캔과 대조할 것. 열람기에서 번역·영문을 나란히 놓고, 썸네일이나 본문의 면 표시를 눌러 스캔을 여는 흐름을 전제로 만들었다.
- **손글씨·도장·여백 메모는 OCR이 대부분 놓친다.** 이 자료는 타자기 본문이 주라 영향이 적지만, 결재 도장이나 손으로 쓴 배포처는 누락된다고 봐야 한다.
- **표와 다단 레이아웃은 줄 재구성이 흐트러진다.** `ocr_pages.py`의 `LINE_TOL`을 조정하면 나아지지만 완전하지는 않다.
- **`confidence: low` 면은 신뢰하지 말 것.**
