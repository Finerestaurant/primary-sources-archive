# 조선 첩보, 뉴욕 1945 — 만드는 차례

```
1. raw/            CREST 본문을 옮겨 놓는다 (crest_ids.json 에서 고름)
2. 옮긴다           서브에이전트. raw/<번호>.txt 하나 → tr/<번호>.json 하나
3. make_docs.py    reading/docs.json 을 짓는다
4. ../열람기/build_site.py
```

## 옮기는 것은 서브에이전트가 한다

**`pi` CLI 를 쓰지 않는다.** 앞선 두 문서철(`KOREA_1950_53`, `NDL_점령기자료`)은
`translate.py` 가 `pi` 를 껍데기로 불러 돌렸는데, 이 문서철부터는 서브에이전트에
맡긴다.

한 에이전트에 문서 몇 건을 주고, 규칙(`TRANSLATION_SPEC.md`)을 읽은 뒤
`tr/<번호>.json` 을 직접 쓰게 한다. 여러 에이전트를 나란히 돌린다.

에이전트에게 주는 것은 셋뿐이다.

    맡을 문서 번호        L01 L02 …
    규칙                pipeline/TRANSLATION_SPEC.md
    말투                ../열람기/STYLE.md

**왜 바꿨나.** `pi` 는 한 번 부르면 한 번 답하고 끝이라, 4만 자짜리 문서를
조각내고 다시 붙이는 일을 `translate.py` 가 떠맡아야 했다(`MAX_CHARS`,
`TAIL`, 조각 합치기). 에이전트는 스스로 파일을 나눠 읽고 나눠 쓴다. 긴 문서를
`Write` 로 뼈대 만들고 `Edit` 로 이어 붙이는 것이 `PLAN.md` 에 적힌 원래 방식
이기도 하다.

## 스캔

`fetch_scans.py` 가 아카이브닷오르그에서 받는다. 309건 702면 · 125MB.
**같은 문서가 두 벌 있어서 한쪽이 죽어 있어도 다른 쪽으로 받는다** — 그것이
이 도구의 핵심이다. 자세한 것은 그 파일 머리에 적어 두었다.

## 이 문서철만의 일 — OCR 교정

FRUS 문서철은 원본 TEI에서 뽑은 정본이라 고칠 것이 없었다. **여기는 스캔에서
기계로 읽어 낸 텍스트라 교정이 먼저다.** 그래서 산출물에 `en`(교정한 영문)이
있다. 앞 문서철에는 없던 칸이다.

`raw/` 의 OCR 원본은 그대로 둔다. 교정본과 대조할 것이 있어야 한다.
